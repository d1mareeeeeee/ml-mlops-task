# Контракт учебного агента, версия 1

## Проверяемый путь

`POST /run` → `src/agent.ts` → `Run.create` / `Run.processStream` из
`@librechat/agents@3.9.8` → инструменты → учебный адаптер → ответ модели.
Точка подмены модели: `/mock/v1/chat/completions` (OpenAI-compatible SSE + tool calls).
Это детерминированная модель, не замена всего ответа приложения.
Точка подмены источника: `src/tools.ts`; адаптер `src/adapter.ts` исполняется в обоих режимах.
Версии транзитивных зависимостей закреплены `package-lock.json`.

## Сессии и права

`Authorization: Bearer demo-alice`: только `acc-alice`, номер `10001`.
`Authorization: Bearer demo-bob`: только `acc-bob`, номер `20002`.
Это публичные учебные токены, только для синтетического локального стенда.
Права извлекаются сервером из токена; в аргументах инструментов пользователя нет.
Неизвестная сессия: HTTP 401. Попытка прочитать чужой счёт: `status=forbidden`, без данных.

## Вызов

POST `/run`, JSON:
```json
{"message":"Начисления 10001 за 2026-08","mode":"mock","tool_mode":"success"}
```
`mode`: `mock` (по умолчанию) или `real`. `tool_mode`: `success`, `empty`, `timeout`,
`forbidden`, `error`, `injection`. Режим применяется к источнику начислений только
на этот запрос; параллельные запросы не меняют друг другу состояние.
`injection` добавляет постороннюю инструкцию в поле `note` ответа инструмента.

Ответ: `run_id`, `mode`, `model`, версии компонента/агента/данных, `message`, `tool_mode`,
`events`, `answer`. Каждый event содержит `name`, `args`, исходный `source` и
переданный агенту `result`. Тот же объект записывается в `artifacts/runs.jsonl`.
ID запуска связывает все вложенные события; ключи модели и токены сессий не записываются.
HTTP 200 означает, что запуск завершился; это НЕ оценка PASS поведения.
Учебный дефект может давать неверный результат с HTTP 200 — это должен выявить тест.

POST `/tools/get_account`: `{"args":{"account_number":"10001"}}`.
POST `/tools/get_charges`: `{"args":{"account_id":"acc-alice","period":"2026-08"},"tool_mode":"success"}`.
Эти маршруты вызывают те же инструменты и позволяют проверить права напрямую.

Входы инструментов заданы Zod-схемами в `src/contract.ts`:
номер — строка из 5 цифр, период — YYYY-MM с месяцем 01–12.
Выход: `{status:"ok",data:...}` или `{status:"not_found"|"forbidden"|"timeout"|"error",message:string}`.
Счёт: `{id,account_number}`. Начисление: `{id,account_id,period,amount_kopecks}`.
`get_account` возвращает один объект, `get_charges` — массив.
Режимы timeout/error должны сохраняться как неуспех по контракту.

## Эталонные данные и ограничения

Источник: `fixtures/data.json`. За 2026-08: Alice — 150000 коп., Bob — 990000 коп.
За 2026-09 начислений нет. Статус ok + пустой массив означает успешное чтение без начислений.
Отсутствующий номер или период требует уточнения, неизвестный счёт — not_found.
Мок распознаёт номер из 5 цифр и месяц YYYY-MM; это ограниченная тестовая модель,
не оценка естественного языка и не доказательство стойкости реальной LLM к injection.
Сравнивайте статусы, аргументы, суммы и свойства ответа.
Каждый запрос запускает новый граф. История диалога в учебный граф не передаётся;
сценарии с историей вне стартового контракта. В UI начинайте новый чат для каждого случая.

Реальная модель: организатор заполняет MODEL_API_KEY, MODEL_BASE_URL, MODEL_NAME в `.env`.
Нужна OpenAI Chat Completions-compatible модель с streaming и tool calling.
Без ключа/имени `/run` с mode=real возвращает HTTP 503 и BLOCKED.
Остальные HTTP 500 требуют диагностики: не считать их успешными проверками.
