## Установка и одна команда проверок

```bash
cp .env.example .env
npm ci
uv sync --frozen --group dev
./scripts/check.sh
```

`check.sh` — единственная команда обязательных проверок. Семь шагов, первый же провал
прерывает скрипт и код возврата доходит до вызывающего:

| № | Шаг | Где |
|---|---|---|
| 1 | `docker compose up -d --build --wait` | — |
| 2 | `npm run typecheck` | контейнер |
| 3 | `npm test` — 6 тестов | контейнер |
| 4 | `ruff check .` | хост |
| 5 | `ty check scripts` | хост |
| 6 | `pytest` — 3 теста на функции-проверки | хост |
| 7 | `evaluate.py` — 9 сценариев агента | хост |

Шаги 1–3 идут в контейнере на закреплённом Node 24.14.0 (образ по digest), шаги 4–7 на
хосте: в образе нет Python. Evaluator ходит в контейнер по HTTP на 8091.

Платный API не нужен: обязательный набор работает на моке.

Контейнер в конце не останавливается — при провале нужны логи. Остановить:
`docker compose down`.

Этот же скрипт вызывает CI ([.github/workflows/starter.yml](.github/workflows/starter.yml)),
поэтому проверка, добавленная в скрипт, попадает в CI без правки workflow.

## Схема проверяемого пути

```
POST /run  (порт 8091 снаружи, 8090 внутри контейнера)
  │
  ├─ src/server.ts      токен сессии → список разрешённых счетов
  │                     права берутся из токена, не из аргументов модели
  │
  ├─ src/agent.ts       Run.create / processStream из @librechat/agents@3.9.8
  │   │                 ← проверяемый компонент, подмене не подлежит
  │   │
  │   ├─ модель ─────→  /mock/v1/chat/completions      ◄ точка подмены модели
  │   │                 src/mock-model.ts
  │   │
  │   └─ инструменты ─→ src/tools.ts                   ◄ точка подмены источника
  │                       get_account, get_charges
  │                       └─ src/adapter.ts            ◄ участок изменения
  │
  ├─ artifacts/runs.jsonl   запись с run_id: события, source, result, ответ
  └─ ответ агента
```

Две точки подмены — модель и источник данных. Сам агентный компонент LibreChat не
подменяется: проверяется реальный путь.

## Правила PASS / FAIL / BLOCKED

Статусы ставит [scripts/evaluate.py](scripts/evaluate.py) по каждому сценарию.

| Статус | Когда |
|---|---|
| **PASS** | HTTP 200 и все проверки свойств сошлись |
| **FAIL** | проверка не сошлась, либо HTTP 400 / 500 |
| **BLOCKED** | HTTP 503, либо соединение не установлено |

HTTP 400 и 500 считаются FAIL, а не блокировкой: `CONTRACT.md:63` требует не считать их
успешными проверками. BLOCKED — только недоступность окружения или невыданный ключ
модели.

Проверяются **свойства**: статусы, аргументы вызовов, суммы, число событий. Свободный
текст ответа модели не сравнивается (`CONTRACT.md:56`). Ко всем сценариям автоматически
применяется проверка `source.status == result.status` — журнал не должен расходиться с
источником.

Коды возврата команды:

| Код | Когда |
|---|---|
| `0` | все сценарии PASS |
| `1` | есть FAIL |
| `2` | FAIL нет, но есть BLOCKED |

Набор фиксируется отпечатком — хешем файла со сценариями, он печатается в шапке отчёта.
Проверить независимо: `shasum -a 256 scripts/evaluate.py | cut -c1-12`.

Прогон на реальной модели — отдельной командой, в обязательный набор не входит:

```bash
uv run python scripts/evaluate.py --real
```

Без `MODEL_API_KEY` даёт 3 BLOCKED и код `2`. Это не FAIL: блокировка провайдера
фиксируется отдельно.

## Воспроизведение сбоя и проверка исправления

Дефект и фикс лежат в истории, поэтому воспроизводятся без правки файлов вручную.

**Воспроизвести сбой:**

```bash
git show 911cba3:src/adapter.ts > src/adapter.ts
docker compose up -d --build --wait
docker compose exec -T agent npm test                  # 4/6, падают 2 теста
uv run python scripts/evaluate.py --out /tmp/before.json   # 8 PASS / 1 FAIL, код 1
```

**Вернуть исправление:**

```bash
git restore src/adapter.ts
docker compose up -d --build --wait
docker compose exec -T agent npm test                  # 6/6
uv run python scripts/evaluate.py --out /tmp/after.json    # 9 PASS, код 0
```

Пересборка обязательна: код запекается в образ через `COPY`, а не монтируется.

**Разобрать сбой по логу:**

```bash
uv run python scripts/explain_run.py 4efce473-0caf-483a-8f56-fdb3dca9d188
```

Показывает расхождение `source=timeout` против `result=ok` и возвращает код `1`.
Готовый разбор — [artifacts/failure-analysis.md](artifacts/failure-analysis.md).

## Потраченное время, ограничения, незавершённое

**Время:** около 11 часов активной работы при лимите 12.

### Ограничения

- **Реальная модель не проверена.** `MODEL_API_KEY` не выдан, прогон `--real` даёт
  3 BLOCKED. Все результаты получены на детерминированном моке. Поведение реальной LLM
  результатами на моке не подтверждается.
- **Инъекция на моке проходит по конструкции.** `src/mock-model.ts` поле `note` не читает
  вообще, поэтому сценарий S7 не доказывает стойкость реальной модели
  (`CONTRACT.md:54-55`). Это проверка проводки, осмысленный результат даст только
  `--real`.
- **Зеркало сценария с чужим счётом не покрыто.** S9 проверяет, что вторая сессия читает
  свой счёт успешно, но обратный случай — `demo-bob` просит счёт Алисы и получает
  `forbidden` — не проверен. Путь отказа проверен только со стороны `demo-alice` (S5).

## Запуск

Требуется Docker Engine/Desktop с Compose v2+, интернет для первой сборки.
Ориентир по ресурсам: 4 ГБ свободной RAM и 8 ГБ диска.
Проверено на Linux amd64; на другой архитектуре организатор сначала проверяет запуск
или выдаёт удалённую среду. При занятом порте измените PORT в `.env`.

```bash
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -e AGENT_URL=http://localhost:8090 agent npm run preflight
```

Последняя команда выполняет полный агентный цикл на mock без платного API.
API: `http://localhost:8091`. Логи: `artifacts/runs.jsonl`.

```bash
curl http://localhost:8091/run \
  -H 'Authorization: Bearer demo-alice' \
  -H 'Content-Type: application/json' \
  -d '{"message":"Начисления 10001 за 2026-08","mode":"mock","tool_mode":"success"}'
```

## Разработка

Node 24.14.0 (`.nvmrc`), `npm ci`, `npm run typecheck`, `npm test`.
Без Node на хосте: `docker compose exec agent npm run typecheck` и `docker compose exec agent npm test`.
После изменения файлов пересоберите контейнер: `docker compose up -d --build --wait`.
Для запуска сервера на хосте: `PORT=8091 npm start` (сначала остановите Docker-сервис).
Python 3.12 + uv 0.11.6: `uv sync --frozen`, `uv run python scripts/sample_run.py`.
В примере один вызов API; evaluator и сценарии по PDF реализует кандидат.
Начальные npm-тесты проверяют инфраструктуру и не означают отсутствие учебного дефекта.

## Реальная модель

Организатор отдельно выдаёт coding agent и доступ к модели с квотой.
Заполните MODEL_* в `.env`, затем `docker compose up -d --force-recreate agent`.
Пример: `RUN_MODE=real uv run python scripts/sample_run.py`.
Ключ хранится только в `.env`, сервер не передаёт его клиенту. Не включайте `.env` в сдачу.
Прогон реальной модели до выдачи ключа имеет статус BLOCKED; mock его не заменяет.

## Сброс и сдача

Данные инструментов неизменяемые; каждый `/run` — новый граф без истории.
Сброс процесса: `docker compose restart agent`. Предыдущие JSONL не влияют на новые запуски;
сохраняйте их как доказательства, не очищайте перед сдачей.
Остановка: `docker compose down`.
Настройки coding agent, два skills, требуемые тесты, AI_USAGE.md и отчёт создаёт кандидат.

## Участок изменения

`src/adapter.ts` — учебный адаптер из задания: timeout ошибочно становится успешным
пустым результатом. Исправление и регрессионный тест — работа кандидата.
Upstream LibreChat менять не требуется. Целевая среда — настоящий агентный компонент
LibreChat, что допускается PDF; полный web UI для ML не нужен.

## Работа и сдача через GitHub

Создайте отдельный репозиторий **в своём GitHub-аккаунте** и перенесите в него
только папку своего задания из стартового комплекта. Работайте и сохраняйте
результат в этом репозитории. Первый коммит — стартовый комплект, последующие
коммиты — изменения по ходу выполнения; сохраните историю работы.

Репозиторий может быть публичным или приватным. Для приватного заранее
предоставьте доступ проверяющему; его GitHub-аккаунт уточните у организатора.
Не публикуйте `.env`, ключи, лицензии и другие секреты.

Для сдачи отправьте:
- ссылку на свой GitHub-репозиторий и SHA финального коммита;
- README с командами запуска и проверок;
- код, тесты, отчёт и остальные артефакты из условия задания.

Одного ZIP-архива или patch вместо GitHub-репозитория недостаточно.
