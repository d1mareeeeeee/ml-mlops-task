# Инструкции репозитория для coding agent

Контракт инструментов и данных: `CONTRACT.md`. Запуск стенда: `README.md`.

## Граница проверки: два разных агента

| | Кто | Что делает |
|---|---|---|
| **Coding agent** | ты | меняешь репозиторий, запускаешь проверки |
| **Продуктовый агент** | `@librechat/agents@3.9.8` | отвечает пользователю; его поведение мы проверяем |

Проверяемый компонент — `Run.create` / `run.processStream` в `src/agent.ts:14-22`.
**Его нельзя подменять** собственным агентом на Python или TypeScript. Подменять можно только модель
(`/mock/v1/chat/completions`) и источник данных (`src/tools.ts`).

## Команды

Node-окружение установлено (`npm ci`), Python-окружение готово (`uv sync`).

| Что | Команда | Где |
|---|---|---|
| Типы TypeScript | `npm run typecheck` | хост, ~1 сек |
| Тесты TypeScript | `npm test` | хост, ~1 сек |
| Сборка и запуск | `docker compose up -d --build --wait` | контейнер |
| Полный агентный цикл | `docker compose exec -T -e AGENT_URL=http://localhost:8090 agent npm run preflight` | контейнер |
| Сервер на хосте | `PORT=8091 npm start` | хост, быстрая отладка |
| Lint Python | `uv run --group dev ruff check .` | **только хост** |
| Типы Python | `uv run --group dev ty check scripts` | **только хост** |
| Тесты Python | `uv run --group dev python -m pytest` | **только хост** |
| Разбор прогона | `uv run python scripts/explain_run.py --last` | хост |

Авторитетным считается прогон в контейнере: там закреплены Node 24.14.0 (по digest
образа) и версии из `package-lock.json`. На хосте Node может отличаться.

## Три ловушки стенда

1. **Два порта.** Внутри контейнера сервер слушает `8090`, наружу проброшен `8091`.
   Из `docker compose exec` обращайся к `8090`, с хоста — к `8091`.
2. **В образе нет Python.** Контейнер Node-only. Python-часть (evaluator, разбор логов)
   работает на хосте и ходит в контейнер по HTTP на `8091`.
3. **Код запечён в образ, а не смонтирован.** Монтируется только `./artifacts`.
   После правки любого файла в `src/` обязателен `docker compose up -d --build --wait`,
   иначе проверяется старая версия кода.

## Где хранится результат

Всё в `artifacts/`:

- `runs.jsonl` — лог прогонов, пишется автоматически из `src/agent.ts:26`;
- отчёты проверок и сравнения «до/после» — туда же.

**JSONL не очищать.** `README.md:50-51` требует сохранять прошлые прогоны как
доказательства. Для разделения «до» и «после» фильтруй по `run_id`, а не удаляй файл.

## Факты контракта

Чтобы не выдумывать значения:

- Статусы ответа инструмента: `ok`, `not_found`, `forbidden`, `timeout`, `error`.
  Режимы `timeout` и `error` обязаны оставаться неуспехом (`CONTRACT.md:47`).
- Токены сессий: `demo-alice` → счёт `10001`, `demo-bob` → счёт `20002`.
  Неизвестный токен — HTTP 401. Права берутся из токена, не из аргументов модели.
- За `2026-08`: Alice — `150000` коп., Bob — `990000` коп. За `2026-09` начислений нет.
- `status=ok` с пустым массивом — это **успешное чтение пустого периода**, и это не то
  же самое, что недоступность источника.
- **HTTP 200 не означает PASS** (`CONTRACT.md:35-36`). Дефект даёт неверный
  результат именно с кодом 200.
- Каждый `/run` — новый граф **без истории диалога** (`CONTRACT.md:57`). Сценарии
  с продолжением диалога вне контракта.
- `tool_mode` действует только на текущий запрос.
- `mode=real` без `MODEL_API_KEY`/`MODEL_NAME` → HTTP 503 и статус BLOCKED.
  Это не FAIL: блокировку провайдера фиксируем отдельно.
